--------------------------------------------------------------------------------

Gemini Health Assistant. UI: English + Urdu. Currency: PKR. TZ: Asia/Karachi.

4. ROLES & WORKSPACES (critical)
--------------------------------------------------------------------------------
Roles (packages/shared/src/types/enums.ts):
  patient | doctor | nurse | physiotherapist | rider | admin | super_admin

Workspaces → home paths (packages/shared/src/auth/workspace.ts):
  patient → /dashboard
  doctor → /doctor
  admin → /admin
  nurse → /nurse
  physiotherapist → /physiotherapist
  rider → /rider   (role/proxy exist; NO rider app pages yet)

Dual-role rules (do not break):
- Clinical signup = patient + staff role (auth.service.ts roleByAccountType)
- canUsePatientWorkspace(roles, activeWorkspace): staff may use patient UI ONLY
  when activeWorkspace === "patient" (packages/shared/src/auth/rbac.ts)
- getAvailableWorkspaces includes patient for anyone with patient role (incl. staff)
- Default workspace prefers clinical staff over admin (resolveDefaultWorkspace)
- Switch: session.update({ activeWorkspace }) then navigate
  (app-user-menu.tsx, workspace-switcher.tsx)
- Legacy clinical users without patient: POST /api/v1/auth/sync-session
  (triggered from app-header-user.tsx)
- Health Assistant: any account with patient role (canAccessHealthAssistant)

Key auth files:
  apps/web/src/lib/auth/auth.config.ts   edge-safe Auth.js config
  apps/web/src/lib/auth/auth.ts          Node providers + jwt
  apps/web/src/lib/auth/routes.ts        public paths, post-auth redirects
  apps/web/src/proxy.ts                 role + workspace + verification gates
  packages/shared/src/auth/rbac.ts
  packages/shared/src/auth/workspace.ts
  apps/web/src/server/services/auth.service.ts
  ADMIN_ALLOWLIST_EMAILS → admin-allowlist.ts

9. AGENT RULES (product + architecture)
--------------------------------------------------------------------------------
1. Gate patient surfaces with canUsePatientWorkspace(roles, activeWorkspace),
   not bare Roles.PATIENT — dual-role staff must switch workspace first.
2. New clinical accounts always get patient role + PatientProfile.
3. Workspace switch = update activeWorkspace THEN navigate.
4. proxy.ts enforces role + workspace match on /doctor|/admin|/nurse|
   /physiotherapist|/rider and staff verification redirects.
5. Patient onboarding gate runs only when canUsePatientWorkspace is true
   (so doctors are not trapped on /onboarding while in doctor workspace).
6. Prefer editing existing feature/service files; do not invent parallel stacks.
7. Keep en + ur dictionary keys aligned when adding UI copy.
8. Do not commit .env / secrets. Do not force-push main.
